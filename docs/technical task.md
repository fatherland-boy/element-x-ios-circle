# Техническое задание №1

# Реализация видеосообщений ("Кружочки") в форке Element X iOS

## Общая цель

Реализовать в форке Element X iOS функциональность, аналогичную Video Notes в Telegram.

При этом:

* **НЕ изменять сервер Synapse;**
* **НЕ изменять Matrix Rust SDK;**
* использовать только существующий Matrix Client API;
* сохранить полную совместимость с обычными Matrix-клиентами.

Другие Matrix-клиенты должны видеть обычное видео.

Наш клиент должен отображать его как кружочек.

---

# Главные принципы

Необходимо придерживаться следующих правил.

### Нельзя

* ломать существующую архитектуру Element X;
* изменять существующие сервисы без необходимости;
* копировать код Telegram;
* менять протокол Matrix;
* менять Synapse;
* изменять Rust SDK;
* использовать приватные API iOS.

---

### Нужно

Максимально использовать существующие компоненты Element X.

Новая функциональность должна подключаться через расширение существующей архитектуры.

---

# Этап 1. Исследование проекта

Перед написанием любого кода AI обязан полностью исследовать проект.

Необходимо определить:

* где создаётся Composer;
* где располагается кнопка отправки;
* где открывается камера;
* где начинается загрузка видео;
* где создаётся Timeline;
* где происходит отображение VideoMessage.

Результат исследования оформить в

```text
docs/video-note-research.md
```

---

# Этап 2. Проектирование

Создать документ

```text
docs/video-note-design.md
```

В документе описать:

* архитектуру;
* взаимодействие компонентов;
* жизненный цикл видеосообщения;
* точки интеграции;
* последовательность вызовов.

До утверждения архитектуры код писать нельзя.

---

# Этап 3. Новые компоненты

Создать новые компоненты.

Названия допускается скорректировать под стиль проекта, если существующие соглашения отличаются.

Минимальный набор:

```text
VideoNoteRecorder
VideoNoteProcessor
VideoNoteThumbnailGenerator
VideoNoteUploader
VideoNoteRenderer
VideoNotePlayer
VideoNoteMetadata
```

Каждый класс должен отвечать только за одну задачу.

---

# Этап 4. Интерфейс записи

Необходимо реализовать новый элемент интерфейса.

Требования:

* кнопка возле поля ввода;
* поддержка удержания;
* отпускание завершает запись;
* отмена через свайп влево (желательно);
* отображение таймера;
* отображение состояния записи.

Не использовать системный UIImagePickerController.

Использовать собственную реализацию на AVFoundation.

---

# Этап 5. Запись видео

Использовать

```text
AVCaptureSession
```

или современный аналог AVFoundation.

Записывать:

* MP4;
* H.264;
* AAC;
* квадратное видео;
* фронтальная камера по умолчанию;
* возможность переключения камеры оставить на будущее.

Продолжительность ограничить:

```text
60 секунд
```

---

# Этап 6. Обработка видео

После завершения записи выполнить обработку.

Минимальная обработка:

* привести к квадрату;
* нормализовать разрешение;
* при необходимости уменьшить битрейт;
* сохранить MP4.

Предпочтительно использовать AVFoundation.

FFmpeg подключать только если AVFoundation не позволяет выполнить требуемые операции.

---

# Этап 7. Генерация превью

После обработки получить thumbnail.

Использовать первый информативный кадр.

Размер превью должен соответствовать существующим требованиям Element X.

---

# Этап 8. Отправка

Не создавать новый тип Matrix-сообщения.

Использовать стандартное:

```text
m.video
```

Добавить собственное поле.

Например:

```json
{
  "org.mychat.video_note": true
}
```

Либо другое пространство имён проекта.

Поле должно быть документировано.

---

# Этап 9. Загрузка

Использовать существующий UploadService проекта.

Нельзя реализовывать собственный HTTP-клиент.

Нельзя дублировать загрузку файлов.

---

# Этап 10. Отображение

При получении сообщения:

если

```text
org.mychat.video_note == true
```

то необходимо использовать новый Renderer.

Иначе использовать существующий Video Renderer.

---

# Этап 11. Renderer

Создать отдельный Renderer.

Требования:

* круглая маска;
* прогресс воспроизведения;
* кнопка Play;
* поддержка паузы;
* отображение длительности.

Не менять существующий Renderer обычных видео.

---

# Этап 12. Player

Создать отдельный Player.

Использовать:

```text
AVPlayer
```

или существующий VideoPlayer Element X.

Не создавать новый медиадвижок.

---

# Этап 13. Локальное хранение

Использовать существующий механизм кэширования медиа.

Не создавать отдельный каталог хранения.

---

# Этап 14. Получение сообщений

При получении события:

проверять наличие

```text
org.mychat.video_note
```

Если отсутствует

использовать обычный Video Bubble.

Если присутствует

использовать VideoNote Bubble.

---

# Этап 15. Архитектура

Жизненный цикл должен выглядеть следующим образом.

```text
Composer

↓

VideoNoteRecorder

↓

VideoNoteProcessor

↓

ThumbnailGenerator

↓

UploadService

↓

Matrix Server

↓

Timeline

↓

VideoNoteRenderer

↓

AVPlayer
```

---

# Этап 16. Совместимость

Необходимо обеспечить совместимость.

Element X:

отображает кружочек.

Другие Matrix-клиенты:

видят обычное видео.

Никаких ошибок возникать не должно.

---

# Этап 17. Производительность

Избегать:

* повторной перекодировки;
* лишнего копирования файлов;
* хранения нескольких копий видео;
* блокировки главного потока.

Вся обработка должна выполняться асинхронно.

---


Описывать:

Код должен соответствовать существующему стилю проекта.

Перед созданием новых компонентов необходимо проверить, нет ли аналогичных реализаций.

Запрещается:

* создавать дубли;
* переписывать существующие сервисы без необходимости;
* изменять публичные интерфейсы без документированного обоснования.

---

# Definition of Done

Функция считается завершённой только если выполняются все условия:

* можно удержанием начать запись;
* запись завершается отпусканием;
* создаётся квадратное MP4;
* генерируется превью;
* видео загружается через существующий UploadService;
* отправляется как стандартное `m.video` с пользовательским флагом `org.mychat.video_note`;
* в Element X сообщение отображается круглым видеосообщением;
* воспроизведение работает корректно;
* обычные Matrix-клиенты отображают это сообщение как обычное видео;
* существующий функционал отправки фото и видео не нарушен;
* проект успешно проходит сборку в GitHub Actions на macOS.
